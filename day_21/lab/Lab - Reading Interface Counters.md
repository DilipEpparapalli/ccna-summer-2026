## Mission Briefing

Coffee House Beta's router is finally passing traffic, but Jeremy wants you to prove the link is healthy. Today you will read the raw interface counters, spot symptoms such as CRCs and collisions, and confirm you can recognize a duplex mismatch when it appears. Finish with a clean bill of health for `Cafe-RT1` and its uplink to `Cafe-SW1`.

## Training Objectives

For this deployment to be successful, you must complete the following:

- Capture the key statistics from `Cafe-RT1`'s LAN interface (speed/duplex status, load, CRCs, collisions, resets).
- Demonstrate how a duplex mismatch reveals itself in the counters and returns to normal once corrected.
- Correlate the router's view with the switch's MAC table so future troubleshooting starts from known data.

## Task 0 - Capture the Baseline

Establish a snapshot of the router's LAN interface before you make any changes.

**Steps:**

- Sign in to `Cafe-RT1`, move to the privileged prompt if needed, and examine Ethernet0/0 so you know its MAC address, negotiated speed/duplex, and current load figures.
- Record the five-minute input/output rates plus the cumulative packet and byte counters for Ethernet0/0.
- Note the CRC, input error, collision, and reset counters so you have a baseline for comparison later.
- Remember that an embedded IP SLA echo to `Cafe-PC1` (192.168.10.100) keeps light traffic flowing, so the counters will continue to tick even when you are not generating packets manually.

## Task 1 - Confirm the Switch Learns the Router

Correlate the router's counters with the access switch so you know exactly where the link lands.

**Steps:**

- On `Cafe-SW1`, review the MAC address table and identify which port is learning the router's MAC address.
- Document the switch interface number and confirm the MAC matches what you observed on Ethernet0/0.
- Add a short note in your site log tying the router's MAC to the switch port.
- The router MAC is generated by the lab environment, so use the exact MAC from your `show interface ethernet0/0` output.

## Task 2 - Observe a Duplex Mismatch in Action

Introduce yourself to what a duplex mismatch looks like by comparing the lab output to a real-world sample.

**Steps:**

- On `Cafe-RT1`, run `show interface ethernet0/0 | include line protocol|Full-duplex|input errors|output errors|CRC|collisions|resets` so you can capture how the counters look while the link is healthy.
- Compare your live output to the sample duplex-mismatch snippet so you can see how CRC errors and collisions jump when the link is misaligned.
- Document the differences so you can describe which counters would spike during a real duplex mismatch versus what you see in the lab right now.

```

  MTU 1500 bytes, BW 100000 Kbit/sec, DLY 100 usec,
```
